# 测试、排错与发布

[目录](README.md) · [English](../en/testing.md) · [本次验证记录](../VALIDATION.md)

模组写好之后，我们先在自己的游戏里试一遍，确认图片、文字和效果都符合预期，再打包分享。这一篇会介绍查看日志、使用测试指令和上传创意工坊的方法。

## 1. 先看看日志

本教程参考[当前源码](../SOURCE.md)编写，你在 Steam 安装的游戏可能还没有包含其中的新功能。建议先只安装 `00_hello`，确认它能运行，再逐个添加其他示例，方便找到具体是哪一步出了问题。

如果某个功能没有反应，也要留意游戏版本。安装模组不会自动升级游戏，例如旧版本可能直接忽略材质包清单，并且不报错。

想检查游戏里有没有某个类型，可以临时在 `init()` 中加上下面这段代码。这里以牌面配色接口为例：

```lua
local ok, result = pcall(function()
    return typeof(CS.Aotenjo.TileFaceMaterialRegistry)
end)
CS.Aotenjo.Logger.Log("TileFaceMaterialRegistry available: " .. tostring(ok and result ~= nil))
```

日志显示类型存在后，再实际运行对应示例，确认要调用的方法也能使用。配色示例会用 `assert` 检查注册结果，如果失败，可以接着查看详细的 Lua 错误。

AML 日志的位置在[快速上手](quickstart.md)中已经介绍过。名称或翻译出错时，还要看看同一个 persistentDataPath 下的 `Player.log`，有些本地化错误只会写到那里。

日志中也可能出现不影响使用的提示。例如，一个没有图片的纯脚本模组可能提示 `No textures directory found`。这时先检查 Lua 有没有报错，以及示例的成功日志有没有输出，不用因为缺少图片目录就认定整个模组加载失败。

## 2. 开启测试控制台

为了方便拿到刚做好的遗物和牌，可以在测试模组的 `init()` 中临时加上 `CS.Constants.CONSOLE_ENABLED = true`。保存后完整重启游戏，开一个测试用的新局，按 F2 打开控制台。

这里的 `Constants` 是游戏运行时的全局类型，没有包含在本次公开源码中。旧版本或其他平台可能没有这个开关；如果它报错，先删掉这一行，通过正常游玩和图鉴检查已有功能，并记下测试的游戏版本。测试请使用单独的新存档，发布模组时也要删掉这个调试开关。

控制台中常用的指令如下：

| 指令 | 例子 | 作用 |
| --- | --- | --- |
| `give` | `give tutorial_artifact:coin_twos` | 获得已注册遗物；正常槽位与规则仍适用 |
| `addSlot` | `addSlot 3` | 增加3个槽位，便于组合测试 |
| `setHand` | `setHand 222m333p` | 替换手牌；m万、p饼、s索、z字牌；不要在正在计分时调用 |
| `setMat` | `setMat 0-2 tutorial_gems:ruby` | 设置索引0、1、2的材质，区间两端都包含 |
| `setFont` | `setFont 0 blue` | 改第0张手牌字体，便于观察配色 |
| `earn` | `earn 20` | 增加20金币 |
| `upgradeYaku` | `upgradeYaku custom_yaku:tutorial_yaku:all_twos 1` | 增加1级，不是设为1级 |
| `seed` | `seed` | 显示当前种子 |
| `help` | `help` | 列出当前发行版可用命令 |

记不清指令时，可以先输入 `help`，查看当前版本支持的用法，再按错误提示调整。不同指令的下标和范围规则也可能不同，例如这里 `setMat` 的范围包含末端，但旧版 `setCorrupted` 不能直接套用这个规则。

## 3. 把七个示例各试一遍

先单独安装一个示例，重启游戏，按下面的操作试一遍；各自正常之后，再把它们一起装上，检查是否互相影响。表中列的是进游戏后应该看到的结果，需要在你使用的游戏版本中实际确认。仓库里的自动检查没有代替这一步。

| 示例 | 操作 | 应看到的结果 |
| --- | --- | --- |
| Hello | 启动，查看 AML | 一条 `[tutorial_hello] Hello / 你好`；再启动重新出现 |
| 二号硬币 | give；setHand 222m123p；依次打出两组 | 本次二每张+2金币；非二不触发，已落定的二不再次触发 |
| 练习玉 | give tutorial_artifact:practice_jade；计分两次 | 第一次×1.0，第二次×1.1；反复查看说明不增加计数 |
| 全二 | 升级自定义番种；先打222m，再在组合里加入非二 | 纯二组合成立；混入非二不成立；图鉴与火包有对应内容 |
| 宝石 | setMat；计分、完成关卡；新局选教学宝石组 | 红宝石每张+20符，蓝宝石×2番；经过关末效果的红宝石+2金币；组内能抽到材质 |
| 合成 | 依次 give 铜、银代币 | 两个输入消失，双代币出现并+5番；仅有一个输入时不合成 |
| 材质包 | 查看折纸熊图鉴/获得折纸熊 | 硬币图标，原名称与机制；移走包重启恢复 |
| 配色 | 进入新局；setFont 0 blue | 普通牌青绿、蓝字体彩虹；移走包重启恢复 |

基本效果确认之后，再切换中英文，检查文字内容是否一致。对于自己的模组，还要试试普通弃牌和强制弃牌、反复触发、移除后重新获得等情况，看看有没有重复订阅或额外奖励。

带成长数据的遗物，要保存后退出游戏，再续局检查数值；新局则应该按设计重置。自定义材质还要确认不同牌的数据互不影响。和其他模组一起安装时，每个模组的 `init()` 应当各运行一次。

开始测试前，先备份一份还没有使用新增内容的存档，测试用的存档另外保留，方便以后比较和排查。

## 4. 遇到问题时查这里

如果结果和预期不一样，可以先按下面这张表排查。每次只改一处，完整重启后再试，会比较容易找到原因。

| 症状 | 检查和解决 |
| --- | --- |
| 模组完全不显示 | 目录是否多套一层；modinfo.json 是否有效 JSON；真实扩展名 |
| 显示已加载，但没有内容 | AML 是否 `Failed to load Lua script`；函数是否全局 `init`；是否遗漏 BuildAndRegister |
| 自己的代码变成另一模组行为 | `require("util")` 重名缓存；改成带唯一前缀的模块路径 |
| 字典 duplicate key | 同时安装本地与 Workshop 同一份、重复 ID、手动再次调用 init |
| 图标错误 | modID、Create ID、文件名三者一致；PNG 是否位于正确直接子目录 |
| 描述显示键名 | 语言文件名/键名；Yaku 是否缺 `custom_yaku:`；查看 Player.log |
| 牌效果次数过多 | 是否检查 Selecting；是否误把阶段触发当整局触发；是否在查询时修改状态 |
| Nil player 或函数参数错位 | 图鉴 player 可以为空；逐项核对回调签名 |
| 番种不能抽到/不计分 | 注册前置、groups、包索引、稀有度、解锁等级和 predicate 分别检查 |
| 材质已注册却不出现 | 是否创建并选中材质组，普通/稀有池是否非空；先 setMat 验证 |
| 材质包有加载日志却没变化 | target 是否真实匹配；整图尺寸日志；是否被后加载包覆盖；完整重启 |
| 续局失去状态或方法 | 稳定ID、SetData字符串、模组是否还安装；材质委托恢复是单独兼容项 |

## 5. 打包并上传创意工坊

测试完成后，把自己的模组文件夹打包成 ZIP。其他玩家解压到 `mods` 后，应该能直接找到 `mods/你的文件夹/modinfo.json`，里面只放模组需要的文件，不要把游戏 EXE、src、Unity Library、日志或自己的存档一起打包。

示例中的 `img.png` 是预览图，可以换成自己的图片。教程建议先使用512×512以内的尺寸；这个尺寸是制作建议，并不是从当前源码确认的服务端上限。

想发布到 Workshop，先确认本地模组已经能正常运行，再打开游戏的模组管理器，选中它并点击上传至创意工坊。上传时会使用清单中的 name、description、整个模组文件夹，以及根目录的 `img.png`。

上传前保持 Steam 已连接，并按提示完成需要的创作者协议。新项目默认以 Private 状态创建，可以先打开项目页面检查名字、介绍和预览图，确认无误后再改成公开。

第一次上传后，记下自己 Workshop 页面的 item ID。以后更新时，在同一个模组的清单里加上 `"workshopId": "你的item ID"`，再上传就会更新原来的项目。如果没有填写，会创建一个新项目；这里要使用自己的项目 ID。

上传工具不会检查 Lua 效果是否正确，所以发布前还是要把上面的测试做完，删掉调试开关，并在介绍里写清楚测试过的游戏版本、模组版本、依赖、存档兼容情况和本次改动。最后，把准备分享的 ZIP 解压到一个干净的 `mods` 目录，再按玩家的安装方式试一次。
